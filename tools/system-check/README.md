# The system's checks

Cases that check the Lisp system in `sys/`, run on a band through
`tools/lispm-check`, as `tools/microcode-check/` does for the microcode.
Each check is a case file, `cases/NAME.cases`, with the Lisp it needs first,
if any, in `lisp/NAME.lisp`.

```
tools/system-check/run -- --band PACK --ubin UBIN                         # every check
tools/system-check/run interpreter-closure -- --band PACK --ubin UBIN     # one of them
tools/system-check/run interpreter-closure -- --band PACK --ubin UBIN \
    --compile --files sys/sys/eval.lisp                                   # a changed source first
```

Arguments after `--` go to every lispm-check run. A check runs against the
system the band was built with. To check a change to a source before a band is
built from it, compile and load that file first, with lispm-check's
`--compile` and `--files`; a check with its own `lisp/NAME.lisp` then needs
that file named in the same `--files`, as lispm-check takes one list.
lispm-check's default band, `run/check/band.img`, is System 2000's. The exit
status is 0 when every check passes.

| Check | What it checks |
|---|---|
| `float-printing` | An IEEE single's infinity prints as `#.SI:SINGLE-FLOAT-POSITIVE-INFINITY` or `-NEGATIVE-INFINITY` and reads back to the same bits (`sys/io/print.lisp`, `PRINT-FLONUM`; `sys/sys2/numer.lisp`). Run it with the tree's files compiled first: `--compile --files sys/io/print.lisp,sys/sys2/numer.lisp`. The first four cases, finite floats printing as before, are controls. A printer that scales an infinity by powers of ten prints `1.0e153` and fails the two printing cases. |
| `float-reading` | The reader reads a float literal as the correctly rounded IEEE single, to nearest, ties to even (`sys/io/read.lisp`, `XR-FLOAT-BITS`): `1.570796326` is `#x3FC90FDB`, a literal past the largest single an infinity, a halfway one rounds to even, a long digit string just past or short of a halfway point rounds by all its digits, negatives likewise; below the smallest normal single a literal underflows as arithmetic does (`FLOATING-EXPONENT-UNDERFLOW`, or 0.0 under `ZUNDERFLOW`). Run it with `--compile --files sys/io/read.lisp`. The first three cases are controls. A reader that scales 12 digits by a power of ten as floats fails 6 of the 26 (System 2001's step-6 band). |
| `format-float` | `FORMAT`'s float directives (`sys/io/format.lisp`). `~E`, and `~G` when it chooses `~E`, give the float's digits and exponent; they called `SI::SCALE-FLONUM` with a positive number, which it takes negative, and stopped with a subscript or overflow error for every float (System 2000 too). `~G` with no width works. An IEEE single's infinity under `~F`, `~E`, `~G` and `~$` prints as the printer prints it, right-justified in the width, or as the overflow characters when it does not fit. Run it with the tree's files compiled first: `--compile --files sys/sys2/numer.lisp,sys/io/print.lisp,sys/io/format.lisp`. The first three cases are controls; a band without the changes passes 6 of the 18 (System 2001's Y4 band). |
| `process-interrupt` | Interrupting a waiting process whose stack group holds a register of all ones, as the microcode's `SETO` leaves `M-K` and `M-E`: `SI:%POINTER-TYPE-P` (`sys/sys2/lmmac.lisp`) takes a code past `DTP-CHARACTER` as no pointer, so `EH::SG-SAVE-STATE` does not follow the word to address 37777777777, past the 28-bit space, where the machine halted (at the end of every TELNET session but the last, on the first 40-bit band). Run it with `--compile --files sys/sys2/lmmac.lisp,sys/eh/eh.lisp`. The first three cases are controls; without the change two cases fail and the interrupt halts the machine. |
| `herald-machine-type` | The herald's Machine Type line names the board the machine runs on, the board name of feature words 20-24 (contract quux-fullhd, section 6.5; `SI:BOARD-NAME`, `sys/sys/genric.lisp`; `DESCRIBE-SYSTEM-VERSIONS`, `sys/sys2/patch.lisp`): on muir-sim, either engine, `" Machine Type QUUX on muir-sim"`, its value starting in the Microcode line's column. With `SI:FEATURE-PAGE-FIELD` given a page whose words 20-24 hold a name packed as the contract packs it, 4 characters a word, the low byte first: a 10-character name, a 20-character one with no zero byte after it, which the herald prints whole, a 9-character one in `PRINT-FEATURE-PAGE`'s "Board name" line, and none, for which `SI:BOARD-NAME` is NIL, the line reads `QUUX` alone and the feature page says `(none)`. Run it with `--compile --files sys/sys/genric.lisp,sys/sys2/patch.lisp` on a band built before the change, on muir-sim from the commit that gives the board name. The first two cases are controls. A board name read in the wrong byte order fails 6 of the 13, one read to 16 characters 2, a herald without the name 2, and the band without the change 8. |
| `interpreter-closure` | An interpreted closure made while `DEFAULT-CONS-AREA` is a temporary area leaves the enclosing, still running `LET` intact (`sys/sys/eval.lisp`, `UNSTACKIFY-ENVIRONMENT`). The `LET`'s frame is not forwarded into the temporary area, and after the area is reset and consed in again the `LET`'s variable keeps its value. The first case, a closure made in a permanent area, is the control. A system that conses the copies in the temporary area fails the other two. |
| `interpreter-closure-scope` | Interpreted closures, and the code around them, see the variables in scope (`sys/sys/eval.lisp`, `SERIAL-BINDING-LIST`, `APPLY-LAMBDA-BINDVAR` and `EVAL1`). A closure made in a `LET*` init form sees the variables bound before it, not the one it initializes; the `LET*`'s body sees all of them, shares them with the closure, and still does once the closure has returned; the closure works after the `LET*` has returned. `PROG*` does the same, and so does a lambda's `&optional` or `&aux` init form. The arguments of a call to a local function (`FLET`, `LABELS`) are evaluated where it is called, not in the function's environment. The first five cases are controls, which pass without the fixes: closures over `LET`, a call to an `FLET` function with a constant or a variable bound outside it, a `LET*` of more than 16 variables (built in the heap) and a special variable. The last eight are controls too, with the definitions they need: an applyhook that applies as the stepper does sees the same calls, functions and arguments, and an evalhook the same forms. A system that stores a frame back into the link a closure took, extends it there, or binds a closure's environment before evaluating its arguments fails the other fifteen; one that hands the applyhook the closure instead of its lambda fails the applyhook case. |
| `unsigned-addresses` | Addresses are unsigned (contract G3 revision 14, 10.1 and 10.10), on fixnums whose 32-bit field is an address at, above and across 2^31, none of them referenced, so that it runs on any band: `SI:%POINTER-UNSIGNED` gives 3,489,660,928 for 0xD0000000 and 4,294,967,295 for -1 (it made a negative field more negative); `SI:%MAKE-POINTER-UNSIGNED`, the one function that builds an address constant above 2^31, gives a fixnum whose field is the address; `%POINTER-DIFFERENCE`, `%POINTER-PLUS` and `SI:%POINTER-LESSP` across 2^31, the last unsigned (it ordered by the sign of a modular difference); the printer prints an address past 2^31 without a minus sign (`SI:PRINT-POINTER-FIELD`); and the MAR's page walk (`SI::MAP-MAR-PAGES`) visits each page of a range once, unsigned. Run it with the tree's files compiled first: `--compile --files sys/sys/qrand.lisp,sys/sys2/lmmac.lisp,sys/io/print.lisp,sys/sys/qmisc.lisp`. The first cases of each group are controls; System 2001 without the changes fails 17 of the 32. |
| `fef-tags` | An FEF's instruction words are fixnums, tag 005 (contract G1 2.6; contract G3 revision 14, 8.3 and 10.6), whether fasloaded (`FASL-OP-FRAME`, `sys/sys/qfasl.lisp`) or compiled to core (`LAP-OUTPUT-WORD`, `sys/sys/qclap.lisp`); the cold load wrote them so already. Run it with `--compile --files sys/sys/qfasl.lisp,sys/sys/qclap.lisp,tools/system-check/lisp/fef-tags.lisp`, so that the check's own file is fasloaded by the tree's loader. The first two cases are controls; System 2001 without the changes fails the other two, its instruction words tagged 303 and 203 (dtp-symbol). |
| `mar-range` | `SET-MAR` and `CLEAR-MAR` (`sys/sys/qmisc.lisp`) visit each page from the range's first word's to its last's once (`SI::MAP-MAR-PAGES`): a range from 28 words below a page boundary to 50 words past it traps a write of its last word. The old loop stepped `#o200` words and missed that page. Run it with `--compile --files sys/sys2/lmmac.lisp,sys/sys/qmisc.lisp,tools/system-check/lisp/mar-range.lisp` on any band. Three of its four cases are controls; System 2001 without the change fails the other. |
| `rev14-addresses` | Revision 14's Lisp at, above and across 2^31 words (contract G3 revision 14, section 12's Y3 checks): the region floor and its argument errors, the windows holding no region, `%XBUS-READ`'s base and bound, `%UNIBUS-READ` signalling, the address space map's array filling its area, the commit limit and the free space, an ephemeral region's `%REGION-NUMBER` and a young object's printed address, the page table's readers, and on objects placed across 2^31 with the region floor: the three primitives, `DESCRIBE` of a locative, `ARRAY-INITIALIZE` of a displaced array, `SET-MAR` and `CLEAR-MAR`, `WIRE-ARRAY`, `WIRE-STRUCTURE`, `WIRE-DISK-RQB`, `RQB-DATA-POINTER`, `ADJUST-ARRAY-SIZE`, the micro-compiler's exit vector (`MA-REBOOT`, `MA-LOAD-EXIT-VECTOR-Q`) and `METER:BUFFER-RESET`, the last with a METR partition on the pack. It needs revision 14 and a band of System 2002, and runs on Y4's first band and on the high band. Its cases run in `USER`, so the system's internal names are written `SI:`. `lisp/rev14-partial-fixes.lisp`, given after the check's own file, plants the partial fixes the contract names, and the `SET-MAR` and `WIRE-DISK-RQB` cases must then fail. |
