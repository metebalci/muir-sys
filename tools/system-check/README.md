# The system's checks

Cases that check the Lisp system in `sys/`, run on a band through
`tools/lispm-check`, as `tools/microcode-check/` does for the microcode.
Each check is a case file, `cases/NAME.cases`, with the Lisp it needs first,
if any, in `lisp/NAME.lisp`.

```
tools/system-check/run -- --band PACK --ubin UBIN                         # every check
tools/system-check/run interpreter-closure -- --band PACK --ubin UBIN     # one of them
tools/system-check/run interpreter-closure -- --band PACK --ubin UBIN \
    --compile --files sys/sys/eval.lisp                                   # a changed source first
```

Arguments after `--` go to every lispm-check run. A check runs against the
system the band was built with. To check a change to a source before a band is
built from it, compile and load that file first, with lispm-check's
`--compile` and `--files`; a check with its own `lisp/NAME.lisp` then needs
that file named in the same `--files`, as lispm-check takes one list.
lispm-check's default band, `run/check/band.img`, is System 1001's. The exit
status is 0 when every check passes. The checks of `cases-2mw/` want a machine
of 2 M words of main memory, the CADR's 32 boards (muir's default
`--main-memory-boards`), and run only when named.

| Check | What it checks |
|---|---|
| `interpreter-closure` | An interpreted closure made while `DEFAULT-CONS-AREA` is a temporary area leaves the enclosing, still running `LET` intact (`sys/sys/eval.lisp`, `UNSTACKIFY-ENVIRONMENT`). The `LET`'s frame is not forwarded into the temporary area, and after the area is reset and consed in again the `LET`'s variable keeps its value. The first case, a closure made in a permanent area, is the control. A system that conses the copies in the temporary area fails the other two. |
| `interpreter-closure-scope` | Interpreted closures, and the code around them, see the variables in scope (`sys/sys/eval.lisp`, `SERIAL-BINDING-LIST`, `APPLY-LAMBDA-BINDVAR` and `EVAL1`). A closure made in a `LET*` init form sees the variables bound before it, not the one it initializes; the `LET*`'s body sees all of them, shares them with the closure, and still does once the closure has returned; the closure works after the `LET*` has returned. `PROG*` does the same, and so does a lambda's `&optional` or `&aux` init form. The arguments of a call to a local function (`FLET`, `LABELS`) are evaluated where it is called, not in the function's environment. The first five cases are controls, which pass without the fixes: closures over `LET`, a call to an `FLET` function with a constant or a variable bound outside it, a `LET*` of more than 16 variables (built in the heap) and a special variable. The last eight are controls too, with the definitions they need: an applyhook that applies as the stepper does sees the same calls, functions and arguments, and an evalhook the same forms. A system that stores a frame back into the link a closure took, extends it there, or binds a closure's environment before evaluating its arguments fails the other fifteen; one that hands the applyhook the closure instead of its lambda fails the applyhook case. |
| `mar-range` | `SET-MAR` and `CLEAR-MAR` visit every page of the range, from the first word's to the last word's (`sys/sys/qmisc.lisp`, `MAP-MAR-PAGES`). `lisp/mar-range.lisp` sets the MAR, for writes, over part of an array of 3000 words. The range from 28 words below a page boundary to 50 past it: a write of its last word traps. The first, second and fourth cases are controls: a write of the first word traps, one outside the range does not, and none once the MAR is cleared. A system whose loops step `#o200` words from the first word, MIT's, fails the third. The last three cases write twice in one `SET-MAR` (`sys/eh/eh.lisp`, `RESTORE-MAR-MODE-FROM-FOOTHOLD`): a break left by a throw (`condition-case`) leaves the MAR on, and the next write traps; the second of them, two breaks proceeded with `:no-action`, is the control. An error handler that leaves the MAR off after a throw, MIT's, fails the other two. |
| `pointer-unsigned` | `SI:%POINTER-UNSIGNED` reads a negative fixnum as its 25-bit pointer field, N + 2^25 (`sys/sys/qmisc.lisp`). The first three cases are controls: a non-negative N is itself, and `SI:%MAKE-POINTER-UNSIGNED`, the inverse, gives the negative fixnum for 2^24 + 5. MIT's, which gives N - 2^25, fails the other four. |
| `wire-range` | `WIRE-WORDS`, `WIRE-STRUCTURE` and `PAGE-OUT-WORDS` take every page from the range's first word's to its last word's (`sys/io/disk.lisp`). `lisp/wire-range.lisp` calls them on an array of 3000 words and reads each page's swap status: the pages wired or made flushable, as offsets from a page boundary inside the array, and every page put back to normal after. The first case, nothing wired or flushable before, is the control, and so is a range within one page for `PAGE-OUT-WORDS`. MIT's `WIRE-WORDS` never wires a range's last page, `WIRE-STRUCTURE` errs, and `PAGE-OUT-WORDS` offers the first page each time: they fail the other six. |
| `format-clauses` | FORMAT's cached clause buffer, `FORMAT-CLAUSES-ARRAY`, holds no clause string it gave back (`sys/io/format.lisp`, `FORMAT-RECLAIM-CLAUSES`; `lisp/format-clauses.lisp`). `FORMAT-PARSE-CLAUSES` conses each clause's string in `FORMAT-TEMPORARY-AREA` and `FORMAT-RECLAIM-CLAUSES` returns it with `RETURN-ARRAY`, but the buffer is kept for the next call and the collector scans it whole, past its fill pointer too, so a string left in it is a pointer to storage given back. After `~[`, `~<` and `~:[`, `FORMAT::FC-HELD` counts the arrays the buffer holds and those lying at or above their region's free pointer. Run it with `--compile --files sys/io/format.lisp,tools/system-check/lisp/format-clauses.lisp` on any band. The first two cases are controls; System 1003 without the change fails the other three, `(3 3)` each (measured). 5 cases, about 100 s on micro with `format.lisp` compiled. |
| `format-clauses-gc` | (`cases-2mw/`, run only when named, on a machine of 2 M words) The collector's halt that a returned clause string causes, planted (`lisp/format-clauses.lisp`): FORMAT's temporary consing goes to an area of the check's own; a call with three clauses gives their strings back with the area's free pointer on a page boundary; two arrays of 1.5 M words force that page out; a call with one clause conses its string at the boundary, so CONSF brings the page back fresh without reading it (`M-DONT-SWAP-IN`) and the second string's words are the fresh fill, `DTP-TRAP`; then `SI:GC-IMMEDIATELY`. A buffer still pointing to the second string makes the scavenger transport it, and `%FIND-STRUCTURE-HEADER`'s scan back from it (`XFSHS1`, `sys/ucadr/uc-storage-allocation.lisp`) meets the first string's `GC-FORWARD` words: ILLOP, `HALT-CONS`, and the machine stops, with no answer to the collection case. Run it with `--compile --files sys/io/format.lisp,tools/system-check/lisp/format-clauses.lisp --timeout 300`. The planting cases are controls and pass either way; without the change System 1003 (microcode 1001) halts in the collection case, ILLOP called from `XFSHS1+2`'s dispatch, muir reporting the stop at PC `XFSHS1+3` (measured on micro). 5 cases, about 3.5 minutes on micro with `format.lisp` compiled. |
| `collapse-pnames` | No symbol keeps the package `COLLAPSE-DUPLICATE-PNAMES` gives back (`sys/sys2/gc.lisp`; `lisp/collapse-pnames.lisp`). It interns every pname in the package "GC Temporary", which makes a new symbol there for each first pname, moves some of those into `WORTHLESS-SYMBOL-AREA`, a static area the collector scans, then kills the package and gives its storage back with `RETURN-STORAGE`. `SI::CP-RUN` makes the package itself, runs it, and counts the symbols of `NR-SYM` and `WORTHLESS-SYMBOL-AREA` whose package it still is. Run it with `--compile --files sys/sys2/gc.lisp,tools/system-check/lisp/collapse-pnames.lisp` on any band. The last three cases are controls; System 1003 without the change fails the first, `(T 25116 2)` (measured). 4 cases, about 95 s on micro with `gc.lisp` compiled. |
| `npaint-text-leave` | The demo's `PAINT-COM-TEXT-LEAVE` forgets the string it gives back (`sys/demo/npaint.lisp`; `lisp/npaint-text-leave.lisp`). The file does not load on this system, so `SI::NTL-RUN` reads that one definition from it, gives it a holding string and calls it: a special still naming the string after `RETURN-ARRAY` names the next string consed there. The second case is the control; System 1003 without the change fails the first, `(T T T)` (measured). 2 cases, about 20 s on micro. |
| `scheduler-simple-wait` | A simple process whose function would wait does not stop the scheduler (`sys/sys2/proces.lisp`, `PROCESS-SCHEDULER-FOR-CADR`; `lisp/scheduler-simple-wait.lisp`). A simple process's function runs in the scheduler, which cannot wait: `PROCESS-WAIT` there throws to `PROCESS-WAIT-IN-SCHEDULER`, whose catch was only around the wait functions, so the scheduler stopped in the cold load stream's debugger and every process and the network with it. The dormant file connection GC, a simple process, met a flavor's method table locked by the TELNET server rehashing it after a flip (`FULL-GC` typed right after `GC-IMMEDIATELY`, no answer). Now the run is given up and the function runs again from its start a tick later. A simple process meets a lock another process holds for 5 s and gets it once it is let go; the dormant file connection GC meets its first host's method table held for 70 s and goes back to sleep. On a band built before the change: `--compile --files sys/sys2/proces.lisp,tools/system-check/lisp/scheduler-simple-wait.lisp`, and the first case starts the scheduler afresh, as a boot does, so that the compiled scheduler runs. Without the change the scheduler stops in the second case, the simple process's `PROCESS-LOCK`, and nothing answers again (System 1003's band, micro, measured: TRAP 1203, `THROW-TRAP`, then the TELNET connection closes); with it, 6 of 6 pass. 6 cases, about 2 minutes on micro with `proces.lisp` compiled. |
| `float-print-least` | The least positive floats print, and their printed text reads back as the same float (`sys/io/print.lisp`, `PRINT-FLONUM`, `SCALE-FLONUM`; `sys/io/read.lisp`, `XR-FLONUM-CONS`, `XR-SMALL-FLOAT`; `lisp/float-print-least.lisp`). The printer made a positive float negative before scaling it, and the least positive float of each format, a mantissa of 1/2 at the smallest exponent, has no negative, since a negative mantissa is normalized to [-1, -1/2): `LEAST-POSITIVE-SHORT-FLOAT` and `LEAST-POSITIVE-SINGLE-FLOAT` signalled "MINUS produced a result too small". A float below about 10^-307 needed a power of ten past the table's 10^307, to print ("The subscript 308 ... was out of range") and to read ("318 is larger than the maximum allowed exponent"); and the least positive short float prints as `2.93872s-39`, just below it, which `SMALL-FLOAT` refused. `SI:FPL-ROUND-TRIP` is T, or the printed text when it reads back as another float. Run it with `--compile --files sys/io/print.lisp,sys/io/read.lisp,tools/system-check/lisp/float-print-least.lisp` on any band. The first six cases are controls: ordinary floats, the least negative short float and two short floats near the least positive one. The cadr line's band and System 1001's without the change fail the other eight (measured); with it all pass. 14 cases, about 3 minutes on micro with both files compiled. |
